# 直播APP技术评定与架构方案

**产品形态：** 秀场娱乐直播（1→N 为主，连麦/PK 为二期）  
**初选栈：** 后端 Rust · 管理端 Vue3 · 客户端 Flutter（App/PC/Web）  
**目标市场：** 可覆盖中国大陆的公网分发 + 多端客户端  
**文档性质：** 综合多方调研后的最终架构裁定（2026）

---

## 1. 结论摘要（给决策者的 10 行内 TLDR）

1. **总体栈可采纳，但“Flutter 全端一等公民”需收窄：** 移动端（观众+主播）用 Flutter；**公网 H5 观看页独立 Vue/React**；PC 仅作主播伴侣，不替代 OBS。  
2. **业务后端用 Rust 模块化单体（Axum + SQLx + Postgres + Redis + NATS），正确且推荐。**  
3. **媒体面绝不进 Rust 进程：** 互动用 LiveKit/TRTC，秀场分发用 SRS 或云直播 + 商业 CDN（HTTP-FLV/HLS）。  
4. **MVP 优先买媒体与 IM 能力：** 腾讯云 CSS/阿里云直播 + 腾讯 IM（或 Centrifugo），自建 SRS 仅作开发/后期降本。  
5. **延迟产品线：** 连麦/PK ≤400ms（WebRTC）；秀场观众 CN 1–3s（FLV）；全球/iOS 2–5s（LL-HLS/HLS）。  
6. **礼物/钱包必须双分录账本 + 幂等键，** 与媒体解耦，经 NATS 异步扇出。  
7. **管理后台用 Vben Admin v5 + Ant Design Vue + Orval(OpenAPI)，** 预览播放器用 mpegts.js。  
8. **中国公网分发必须接持牌 CDN/直播云；** 自建 origin 可以，自建边缘 CDN 不现实。  
9. **10–14 周 MVP：** 开播→观看→聊天→礼物→钱包（沙箱支付）→后台强关/封禁；不做 PK/电商/自建 CDN。  
10. **第一刀工程：** 脚手架 monorepo + 冻结 OpenAPI（auth/user/room/wallet/gift/realtime），媒体/支付/KYC 全部走 Provider 端口。

## 2. 对用户初选栈的评定

| 栈项 | 裁定 | 原因 |
|---|---|---|
| **后端 Rust** | **保留** | 适合房间元数据、礼物热路径、钱包账本、鉴权、管理 API。Axum + Tokio + SQLx 2026 成熟。**不要**用 Rust 写 RTP/RTMP 媒体转发。 |
| **管理端 Vue3** | **保留并具体化** | 采用 **Vben Admin v5 + Ant Design Vue**，与 Rust utoipa OpenAPI 用 Orval 生成客户端。 |
| **Flutter App（iOS/Android）** | **保留，作为主产品面** | 观众播放 + 主播推流（WebRTC/商业 SDK）生产级可行；礼物/弹幕/房间 UI 共享最强。 |
| **Flutter PC** | **降级为二期伴侣端** | cam/mic WebRTC 可用；系统音频环回、多窗口、专业推流不如 OBS/Electron。MVP **不阻塞** PC 对等。 |
| **Flutter Web 公网观众端** | **否决作为主路径** | SEO、播放器生态、冷启动、Safari/浏览器编解码均弱于 JS。公网分享/H5 观看页用 **Vue/React + hls.js/mpegts.js**。 |
| **Flutter Web 内网/主播工具** | **有条件保留** | 登录态房间控制台可接受。 |
| **隐含假设“一套 Flutter 推流+播放通吃全端”** | **必须收窄** | 正确口号：**Flutter 负责移动产品面 + 共享领域包；公网 Web 独立；媒体 I/O 多实现适配。** |

## 3. 推荐总体架构

### 3.1 分层原则

| 平面 | 职责 | 技术 |
|---|---|---|
| **客户端** | UI、播放、推流、礼物动画 | Flutter Mobile；Vue H5；Vue Admin |
| **业务控制面（Rust）** | 账号、房间、钱包、礼物订单、审核、签发 token/推流密钥 | Axum 模块化单体 |
| **实时信令/IM** | 聊天、礼物特效广播、在线、系统通知 | Centrifugo **或** 腾讯 IM |
| **互动媒体** | 连麦/PK/语音房 WebRTC | LiveKit（自建）或 TRTC/Agora（MVP 可买） |
| **广播媒体** | 秀场 1→N 推流、转码、录制 | SRS 开发 / 腾讯 CSS·阿里云直播生产 |
| **CDN 末公里** | 全国多运营商拉流 | 腾讯/阿里/网宿（**永不自建边缘**） |
| **数据** | 事务与缓存与异步 | Postgres + Redis + NATS JetStream + 对象存储 |

### 3.3 关键路径（礼物）

1. Flutter → `POST /rooms/{id}/gifts`（鉴权 + 幂等键）  
2. Postgres 事务：扣减钱包账本 + 写 `gift_orders`  
3. 发布 NATS `gift.sent`  
4. Worker → Centrifugo/IM 频道 `room:{id}`  
5. 全员播放礼物动画；主播收入异步入账  

**媒体与礼物解耦：** 礼物不走视频轨，走 IM/WS。

## 4. 媒体方案

### 4.1 协议决策（定稿）

| 场景 | 协议路径 |
|---|---|
| 主播 OBS/专业编码器 | **RTMP**（兼容）+ **WHIP**（优先演进）+ **SRT**（弱网贡献） |
| App 主播开播（互动） | **WebRTC / WHIP → LiveKit 或 TRTC** |
| 连麦/PK/语音房（≤16） | **端到端 WebRTC SFU** |
| 秀场 1→N 大众观众（CN） | 源站 → CDN → **HTTP-FLV + HLS** |
| iOS Safari / 全球观众 | **LL-HLS / HLS** |
| 录制/回放 | **HLS/DASH VOD** + 对象存储 |
| **禁止** | 互动路径用纯 RTMP 或经典长 GOP HLS |

### 4.2 服务器选型

| 角色 | MVP | 规模化 | 许可 |
|---|---|---|---|
| 互动 SFU | **腾讯 TRTC 或 Agora**（Flutter SDK 快） | 评估 **LiveKit 自建** 控成本 | Apache/商业 |
| 秀场源站 | **腾讯 CSS / 阿里云直播** | **SRS** 自建 origin + 多 CDN 回源 | MIT / 商业 |
| 边缘 CDN | **始终采购** | 腾讯 + 网宿/阿里 多活 | — |
| 备选 origin | — | ZLMediaKit | MIT |
| **避开** | OvenMediaEngine（AGPL 闭源产品风险）、自研 SFU、纯自建中国 CDN | | |

### 4.3 拓扑：MVP vs 规模

**MVP（最快中国可上）**
```
Flutter --TRTC/Agora--> 连麦嘉宾（二期启用；MVP 可先不做）
Flutter/OBS --RTMP--> 腾讯 CSS / 阿里直播 --> CDN(FLV/HLS) --> 观众
Flutter --腾讯 IM--> 聊天/礼物
Rust -- 房间/鉴权/订单/回调
```
- 互动：~200–400 ms  
- 观众：~2–5 s  

**规模混合**
```
Flutter --LiveKit/TRTC SFU--> 台上小 N
Host --WHIP/RTMP/SRT--> SRS origin --转码-->
    --> CDN A/B (FLV/LL-HLS/HLS)
    --> 可选 WHEP VIP 超低延迟档
Rust 控制面 + IM/Centrifugo
```

### 4.4 延迟产品条

| 模式 | 目标 E2E | 可接受上限 |
|---|---|---|
| 连麦/PK | **≤400 ms 中位，P95 ≤500 ms** | 600–800 ms 体感卡 |
| 秀场 CN FLV | **≤3 s** | 5 s 仍常见 |
| 秀场 HLS | **≤5 s** | 8 s（LL-HLS 配错时） |
| 聊天 | ≤300 ms P95 | |
| 礼物扇出 | ≤500 ms P95 | |

### 4.5 转码与编码

- 默认 **H.264**；有客户端能力再开 **H.265** 降带宽。  
- 主播推流典型 720p 2–3 Mbps。  
- 转码/截图/录制：优先云直播能力；自建 SRS 用 DVR/hooks。  
- Rust **只签发** stream key / play URL / LiveKit token，**不处理媒体包**。

### 4.6 中国合规与分发

- **自建 origin 可以**（SRS 开发/混合）。  
- **公网末公里必须持牌直播云/CDN**；不要自建 B12 级边缘。  
- CDN/ICP **不等于** 视听证/网文证；产品资质、实名、内容审核仍是独立架构端口。  
- 推流域名与播放域名分离规划；ICP 提前数月启动。

## 5. 业务后端（Rust）

### 5.1 形态裁定

**MVP = 模块化单体 + 强制侧车**，不是“纯单体”，也不是业务微服务网。

| 进程 | 是否 Day-1 分离 |
|---|---|
| `anylive-api`（Axum 业务 API） | 核心 |
| `workers`（可先同二进制 `--mode=worker`） | 逻辑分离，部署可合并 |
| Centrifugo / 腾讯 IM | **强制外置** |
| LiveKit / SRS / 云直播 | **强制外置** |
| Postgres / Redis / NATS | **强制外置** |
| user/room/gift/wallet 微服务 | **否决到有真实痛点** |

### 5.2 技术组件（定稿）

| 层 | 选型 |
|---|---|
| Runtime / HTTP | Tokio + **Axum 0.8** + Tower |
| OpenAPI | **utoipa** + swagger-ui |
| DB | **PostgreSQL + SQLx 0.8**（钱包路径 compile-time SQL） |
| Cache | **Redis**（OTP、会话、在线、限流、礼物 combo） |
| 事件 | **NATS JetStream**（礼物/订单/审核；Kafka 延后） |
| 实时 | **Centrifugo** 或 **腾讯 IM** |
| 鉴权 | 手机短信 OTP + JWT access(15m) + Redis refresh；可吊销 |
| 金额 | `BIGINT` 金币 + `rust_decimal` 法币；**禁用 f64** |
| 观测 | tracing + OTel + Prometheus 业务指标 |
| 短信 | 阿里云/腾讯云 SMS |
| 媒体集成 | `livekit-api` / SRS http_hooks / 云直播回调 |

### 5.3 Crate 划分（工作区）

```
backend/crates/
  api/           # Axum 入口
  domain/        # 纯领域类型与端口
  db/            # SQLx + migrations
  auth/
  rooms/
  gifts/
  wallet/
  orders/
  moderation/
  media/         # token、stream key、webhook 校验
  realtime/      # Centrifugo/IM 发布
  workers/
  common/        # config、telemetry、error
```

**模块边界 = 未来服务切分线**；跨模块禁止随意写对方表，钱包只走 ledger API。

### 5.4 核心领域表（精简）

`users`, `auth_identities`, `rooms`, `streams`, `gifts`, `gift_orders`(含 `client_request_id` 唯一), `wallets`, `wallet_ledger`(只追加), `pay_orders`, `moderation_reports`, `admin_audit_log`。

### 5.5 Provider 端口（必须）

- `MediaProvider`：推流/播放 URL、录制开关  
- `PayProvider`：充值回调、沙箱→微信/支付宝/IAP  
- `KycProvider`：实名状态机  
- `PolicyEngine`：未成年/区域 `live_enabled`/功能开关  

### 5.6 扩展路径

| 阶段 | 触发 | 动作 |
|---|---|---|
| 0 MVP | — | 模块化单体 + 侧车 |
| 1 | 礼物写放大 | 独立 workers |
| 2 | 5万+ 并发连接 | Centrifugo 多节点；媒体独立扩 |
| 3 | 钱包合规/争用 | 按 user 分片或抽 `wallet-service` |
| 4 | 多区域/分析 | Kafka 二级总线；读副本 |

## 6. 客户端方案

### 6.1 边界（裁定）

| 端 | 策略 |
|---|---|
| **iOS/Android 观众 + 主播** | **Flutter monorepo 主战场**（flavor：audience / streamer） |
| **PC 伴侣** | Flutter Desktop **二期**；专业推流仍引导 OBS |
| **公网 H5 观看/分享** | **独立 Vue（或 React）**，非 Flutter Web |
| **运营后台** | Vue3 Vben，非 Flutter |

### 6.2 包选型（2026）

| 能力 | 包 |
|---|---|
| 状态 | **Riverpod** + codegen；高频 IM 走独立事件管线 |
| 路由 | go_router |
| 模型 | freezed + json_serializable |
| 互动 RTC | **livekit_client** 或 **agora_rtc_engine / TRTC** |
| 观众播放（移动/桌面） | **media_kit** |
| 相机 | camera + 美颜走厂商 SDK/FFI |
| 移动 RTMP | 不作为主路径；优先 WebRTC/商业推流；OBS 兜底 |
| 礼物动画 | **Rive** 主，Lottie 辅；并发上限 |
| 弹幕 | **canvas_danmaku** / CustomPainter，禁止每条 Widget |
| IM | 腾讯 IM SDK 或自建 WS 适配层 |

### 6.3 应用结构

```
apps/
  audience/            # 观众
  streamer/            # 主播
  companion_desktop/   # 二期
packages/
  al_core / al_api / al_im / al_rtc / al_player
  al_room / al_chat / al_gift / al_design
```

### 6.4 性能硬规则

- 播放器 `RepaintBoundary` 与聊天/礼物隔离  
- 礼物合并 combo；全屏礼物并发上限（如 3）  
- 弹幕画布层；点赞可丢弃聚合  
- 重连：**房间快照 REST + 游标续传**，禁止回放礼物风暴  
- Impeller 默认；中端 Android 为预算机  

### 6.5 对“Flutter Everywhere”的最终表述

> **成立范围：** 移动端产品逻辑与 UI 共享。  
> **不成立范围：** 公网 Web 一等观看体验、桌面专业推流、全平台同一 RTMP 实现。  
> **工程口号：** Flutter for mobile product surfaces + shared domain；native web for public watch；media plugins multi-implementation。

## 9. MVP 范围与 4 周启动计划

### 9.1 必须有（Phase 1）

- 手机/密码登录、资料  
- 房间生命周期 + 推/播 URL（MediaProvider）  
- 实时聊天 + 礼物目录/送礼/动画事件  
- 虚拟币钱包 + 双分录 + 充值订单（**可 mock PSP**）  
- 关注 + 首页热门/关注  
- 用户举报 + 管理端：封禁、强关、礼物 CRUD、审核队列、审计  
- 实名 **状态字段 + 接口钩子**（可 stub）  
- 指标：同房设计 **1k CCU**、约 100 路并发直播、全站约 10k 在线  

### 9.2 明确不做（MVP）

PK、多人连麦 SFU、短视频、电商、自建 CDN、完整 AI 审核、复杂推荐、白标多租户。

### 9.3 非功能目标

| 项 | MVP |
|---|---|
| 首帧 | P95 ≤3s |
| 秀场 glass-to-glass | ≤3–5s 目标，HLS ≤8s 可接受 |
| 聊天 | ≤300ms P95 |
| 礼物扇出 | ≤500ms P95 |
| 可用性 | API 99.5% |
| 金钱路径 | 幂等；账本不平衡 = 0 |

### 9.4 四周启动

| 周 | 结果 |
|---|---|
| **W1** | monorepo 骨架；OpenAPI auth/user/room；docker-compose；CI；Flutter/Vue 壳 |
| **W2** | 登录注册、房间 CRUD、MediaProvider(SRS 开发)、Flutter 列表+播放、OBS/手机可推可看 |
| **W3** | realtime 入房聊天、限流+敏感词钩子、关注+首页、双端聊天 <300ms（同区） |
| **W4** | 钱包账本、送礼幂等、礼物动画、mock 充值、Admin 封禁/强关/礼物/举报、1k WS 压测基线、KYC 字段闸门 |

**Phase 1 总窗口：** 约 10–14 周至可内测闭环。  
**验收：** 20 主播 / 500 用户 dogfood；无 P0 账本事故；强关与封禁可用。

## 10. 风险清单与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| ICP/视听等资质周期 | 大陆上线阻塞 | 提前备案；播放走持牌 CDN；`live_enabled` 区域开关 |
| 礼物/打赏监管（清朗等） | 产品改版、税务 | 限额、未成年拦截、审计日志 Day-1 |

| 自建 WebRTC 中国弱网 | 连麦质量差 | MVP **买 TRTC/Agora**；二期再 LiveKit |
| Flutter 播放器碎片 | iOS FLV 痛 | 双路径：互动 WebRTC；广播 FLV/HLS；H5 用 JS 播放器 |
| CDN 出口 vs RTC 分钟费 | 毛利崩 | 台上 RTC，台下 CDN；H.265 降本 |
| 礼物双花/丢单 | 资金事故 | 幂等键 + 事务账本 + NATS 至少一次 + 对账任务 |
| 进程内巨型 WS | API 熔断 | **禁止**；Centrifugo/IM |
| 客户端重连风暴 | 卡死 | 快照+游标，不重放礼物史 |
| 插件停更（Flutter RTMP） | 主播推流断档 | WebRTC/商业 SDK 为主；OBS 兼容 RTMP 永留 |
| “云直播=全合规”误解 | 法务误判 | CDN 只解决分发；资质/审核/实名独立建设 |
| 模块化单体腐化 | 难拆 | crate 边界 + 禁止跨模块 DB 直写 + 端口化第三方 |
| 支付监管 | 上线风险 | PayProvider 可插拔；先沙箱；合规 PSP 再切 |

## 11. 明确不建议做的事

1. **不要** 用 Flutter Web 作为公网主观众端。  
2. **不要** 在 Rust 业务服务内终止 RTP/RTMP 或自研 SFU 作为 MVP。  
3. **不要** Day-1 拆 user/room/gift/wallet 微服务网格。  
4. **不要** 把全站房间 WebSocket 塞进 Axum 进程扛 1k+ CCU。  
5. **不要** 自建中国公网边缘 CDN / 类 Cloudflare 的 BGP 分发。  
6. **不要** 选用 AGPL 媒体服务器（OME）作为闭源核心却不买商业许可。  
7. **不要** 用 f64 存钱；不要无幂等送礼；不要长寿命不可吊销 JWT。  
8. **不要** 信任客户端“我已开播”；必须以媒体 webhook/鉴权密钥为准。  
9. **不要** MVP 做 PK、电商、短视频、完整 AI 审核、白标。  
10. **不要** 把“Flutter Everywhere”写进对外技术承诺；对外表述应为 **移动 Flutter + H5 独立 + 媒体侧车**。  
11. **不要** 用纯 SFU WebRTC 承担百万级被动观众（成本曲线错误）。  
12. **不要** 把桌面 Flutter 当成 OBS 替代品阻塞 MVP。  
13. **不要** 硬编码单一云厂商 SDK 为唯一媒体路径——统一 `MediaProvider`。  
14. **不要** Kafka Day-1；NATS JetStream 足够礼物/订单。  
15. **不要** 把合规（实名/审核/防沉迷/账本）留到 Phase 3——**钩子必须在 MVP schema 里**。
