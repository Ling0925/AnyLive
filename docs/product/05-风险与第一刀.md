## 3. 关键路径（不可并行压缩）

```
OpenAPI v0 冻结
    → 房间 + MediaProvider
        → 客户端可看
            → Centrifugo 聊天
                → 钱包账本
                    → 送礼
                        → Admin 处置
                            → 压测/Dogfood
                                → 商店内测
                                    → 真实支付
                                        → GA
```

连麦（P3）从「MediaProvider + Flutter RTC」分支并行，但**不得**阻塞 P1 礼物闭环。

**缓冲：** 每个大阶段预留 1–2 周；商店审核按 +3 周乐观外的坏情况规划。

## 5. 批准后第一刀（按顺序，约 3–5 天）

> 规划批准后，**先做这些再开功能需求**。

### Day 0–1
1. 初始化 git 仓库与默认分支保护  
2. 创建 monorepo 目录树（backend/apps/contracts/deploy/docs/scripts）  
3. 根 README 指向本规划索引与 ADR  
4. `deploy/docker-compose.yml`：Postgres、Redis、NATS、Centrifugo、SRS、MinIO  
5. 申请：域名、云、Apple/Google、Stripe 测试账  

### Day 2–3
6. Rust workspace：`api` `domain` `db` `common` 空 crate + health  
7. OpenAPI：`auth` `users` `rooms` 草案 + `errors/codes.yaml`  
8. CI：fmt/clippy/test + 前端 lint 占位  
9. Flutter 壳 + Vben 壳 + H5 壳（可运行空白页）  

### Day 4–5
10. MediaProvider trait + SRS 本地实现；OBS 推流文档  
11. 契约评审会 → **冻结 v0.1/v0.2**  
12. 项目管理：导入 Epic E0–E12；看板列 ToDo/Doing/Review/Done  
13. 建立周节奏：三契约 / 五 Demo / 日站会 15min  

**第一刀完成定义：** 新成员按文档 30 分钟内起全套依赖；能打通 health 与一路测试推流。
