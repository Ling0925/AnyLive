## 2. OpenAPI 冻结顺序

| 波次 | 模块 | 冻结目标周 | 主消费方 | 依赖 |
|---|---|---|---|---|
| **v0.1** | `errors` + `auth` + `users` | W1 末 | 全端 | 无 |
| **v0.2** | `rooms` + `media` | W2 | Flutter / H5 / Admin | auth |
| **v0.3** | `realtime`（连接票、聊天发送） | W3–W4 | Flutter / H5 | rooms |
| **v0.4** | `gifts` + `wallet` | W5 | Flutter / Admin | users |
| **v0.5** | `social` | W7 | Flutter | users/rooms |
| **v0.6** | `moderation` + `admin` | W8 | Admin | 全模块 |
| **v0.7** | `pay` webhooks + 充值 API | W9 | 后端 / Flutter | wallet |
| **v1.0-rc** | 聚合稳定版 | W11 | 全端 | P1 退出前 |
| **v1.1** | 连麦/PK API | W22+ | Flutter | media LiveKit |
| **v1.2** | 创作者/分析只读 API | W28+ | Admin / Flutter | — |

### 版本策略

- URL 前缀：`/api/v1/...`
- 文档版本：semver；**次版本**可加字段；**主版本**才允许删字段/改语义
- 废弃字段：`deprecated: true` + 至少保留 2 个里程碑

## 3. 核心 REST 资源（P1 最小集）

### Auth
- `POST /auth/otp/send`
- `POST /auth/otp/verify`
- `POST /auth/token/refresh`
- `POST /auth/logout`

### Users
- `GET /me` · `PATCH /me`
- `GET /users/{id}`

### Rooms
- `POST /rooms` · `GET /rooms/{id}` · `PATCH /rooms/{id}`
- `POST /rooms/{id}/start` · `POST /rooms/{id}/stop`
- `GET /rooms`（首页 feed 可放 social）

### Media
- `POST /rooms/{id}/media/publish` → `{ push_url, stream_key, expires_at }`
- `GET /rooms/{id}/media/play` → `{ play_urls: { hls, ... } }`
- 仅服务端调用 Provider；客户端不持有主密钥

### Realtime
- `POST /realtime/token` → Centrifugo 连接 JWT（含 channels 声明）
- `POST /rooms/{id}/messages` → 落库可选 + 发布 IM

### Gifts / Wallet
- `GET /gifts`
- `POST /rooms/{id}/gifts`  
  Header/`body`: `Idempotency-Key` **必填**  
  Body: `{ gift_id, count, client_request_id }`
- `GET /wallet` · `GET /wallet/ledger`
- `POST /wallet/topups` · `GET /wallet/topups/{id}`

### Pay（充值通道，v0.7+）

设计见 [支付通道接入设计](../architecture/payment-channels.md)。现状仅有 mock `POST /wallet/topups`（`ALLOW_MOCK_TOPUP`）；真实渠道未实现。

- `GET /pay/channels` · `GET /pay/products`
- `POST /pay/orders` · `GET /pay/orders/{id}`
- Webhooks（渠道签名，非用户 JWT）：
  - `POST /webhooks/pay/jeepay`
  - `POST /webhooks/pay/epay`
  - `POST /webhooks/pay/tokenpay`
  - （规划）`POST /webhooks/stripe` · IAP 通知
- 入账：验签通过后幂等 `credit_topup`；`contracts/webhooks/pay.md` 应覆盖 **Stripe / IAP / Jeepay / 易支付 / TokenPay**（文件待建）

### Social
- `POST /users/{id}/follow` · `DELETE ...`
- `GET /feed/following` · `GET /feed/hot`

### Moderation / Admin
- `POST /reports`
- Admin 前缀 `/admin/v1/...`：ban、force_close、gifts CRUD、reports queue、audit

## 4. NATS 事件（JetStream）

| Subject | 触发 | 消费者 | 语义 |
|---|---|---|---|
| `gift.sent` | 送礼事务成功后 | realtime-worker、统计、PK（P3） | at-least-once |
| `room.live_started` | webhook/开播确认 | feed 缓存、通知 | — |
| `room.live_ended` | 停播 | 结算、录制收尾 | — |
| `order.paid` | 支付成功 | wallet 入账 | **必须幂等** |
| `user.moderation` | 封禁/禁言 | realtime 踢人、缓存失效 | — |
| `media.recording_ready` | 录制完成（P2+） | VOD 入库 | — |

### 事件信封（统一）

```json
{
  "event_id": "uuid",
  "type": "gift.sent",
  "occurred_at": "ISO-8601",
  "producer": "anylive-api",
  "payload": {}
}
```

`event_id` 消费者去重表保留 ≥ 7 天。

## 5. Webhook 契约

### 5.1 媒体（SRS / LiveKit / CDN）

| 事件 | 方向 | 校验 |
|---|---|---|
| 推流 on_publish | 媒体 → API | HMAC 或 IP allowlist + stream_key |
| 推流 on_unpublish | 媒体 → API | 同上 |
| 录制完成 | 媒体 → API | 签名 |
| LiveKit room/participant | LiveKit → API | JWT/签名 |

**规则：** 不信任客户端「我已开播」；以 webhook + 服务端状态机为准。

### 5.2 支付（多通道）

| 通道 | Endpoint（草案） | 验签要点 |
|---|---|---|
| Stripe（规划） | `POST /webhooks/stripe` | `Stripe-Signature` |
| Jeepay | `POST /webhooks/pay/jeepay` | 商户 API Key 参数签名 |
| 易支付 | `POST /webhooks/pay/epay` | V1 MD5 / V2 RSA |
| TokenPay | `POST /webhooks/pay/tokenpay` | 按部署的 Token/HMAC |
| IAP | App Store / Google 通知入口 | 平台证书 / OIDC |

**公共规则：**

- 只处理白名单事件/成功态；金额以服务端 `pay_orders` 为准
- 入账幂等：`provider_event_id` 或 `(channel, trade_no)` + ledger `reference = pay:{order_id}`
- 详细字段与状态机见 [payment-channels.md](../architecture/payment-channels.md)

### 5.3 IAP

- App Store Server Notifications v2 / Google RTDN
- 统一映射为内部 `order.paid` / `order.refunded`

## 6. 实时频道约定

| Channel | 谁可订 | 内容 |
|---|---|---|
| `room:{room_id}` | 入房用户 | chat、gift、like、system、pk |
| `user:{user_id}` | 仅本人 | 踢下线、余额变更、审核通知 |
| `admin:ops` | 运营角色 | 告警（可选） |

消息类型枚举：`chat` | `gift` | `like_batch` | `presence` | `room_state` | `pk_state` | `moderation`。

重连策略：**REST 房间快照 + 游标**，禁止重放完整礼物历史。

## 7. 错误码（节选）

```yaml
# contracts/errors/codes.yaml 示例结构
AUTH_INVALID_OTP: { http: 401, retryable: false }
AUTH_TOKEN_REVOKED: { http: 401, retryable: false }
ROOM_NOT_LIVE: { http: 409, retryable: false }
MEDIA_PROVIDER_ERROR: { http: 502, retryable: true }
GIFT_INSUFFICIENT_BALANCE: { http: 402, retryable: false }
GIFT_IDEMPOTENT_REPLAY: { http: 200, retryable: false }  # 返回原结果
WALLET_CONFLICT: { http: 409, retryable: true }
RATE_LIMITED: { http: 429, retryable: true }
FORBIDDEN_POLICY: { http: 403, retryable: false }
```

客户端按 `code` 分支，不依赖英文 `message`。

## 8. 代码生成与门禁

| 消费者 | 工具 | 门禁 |
|---|---|---|
| Admin / H5 | **Orval** → TS client + Vue Query | PR 必须含生成 diff 或 CI 生成后 no-diff |
| Flutter | openapi-generator / 自维护 `al_api` | 模型 freezed；CI 编译 |
| 事件 | JSON Schema 校验（worker） | 消费前 validate |

**契约评审：** 每周三 30min；Owner = 后端 Lead；否决权 = TL。
