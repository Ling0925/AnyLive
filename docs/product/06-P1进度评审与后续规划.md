## 8. 后续规划

### 8.1 原则（必须统一口径）

1. **P1 未签字前，默认冻结新功能面**；只修阻塞 dogfood 的缺陷与验证项。
2. **P3/P4 代码可保留，但必须**：
   - 默认 `FEATURE_PK=0` / `FEATURE_COHOST=0`；
   - 文档标注 **「非 P1 退出条件」**；
   - 独立 PR / 分支叙事，禁止与 P1 出口混谈。
3. **先收敛 git，再扩阶段**；未拆分的大工作区视为不可发布。
4. **出口证据优先于新 API**：OBS 周日志、设备矩阵表、缺陷会纪要、OTP 投递证明。

### 8.2 阶段 0 — 立即（1–3 天）：仓库收口
